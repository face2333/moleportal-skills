# Mole Portal 周维度运营数据 · 第三方使用说明

## 一、你需要准备什么

| 项目 | 是否需要你提供 | 说明 |
|---|---|---|
| MCP 服务地址 | 需要（管理员给你） | 形如 `https://<host>/mcp` |
| MCP Bearer Token | 需要（管理员给你） | 形如 `Bearer <一串字符串>` |
| OpenAPI 的 callerId / security | **不需要** | 已固化在服务器，调用方接触不到 |
| 项目、日期范围 | 需要（你告诉 AI 即可） | 例如"本周"、"2026-08-31 到 09-06" |

**你唯一要配置的鉴权就是 MCP 的 Bearer Token** —— 它相当于进入这个数据服务的门禁，不包含任何业务密钥。业务侧凭据（appId / security）保存在服务端，你既看不到也不用管。

---

## 二、安装步骤

### 1. 接入 MCP 服务

在客户端的 MCP 配置里加一段（WorkBuddy 为 `~/.workbuddy/mcp.json`；其它客户端位置不同，但字段一致）：

```json
{
  "mcpServers": {
    "moleportal": {
      "type": "http",
      "url": "<管理员给你的 MCP 地址>",
      "headers": {
        "Authorization": "Bearer <管理员给你的 Token>"
      }
    }
  }
}
```

### 2. 安装本 Skill

把 `moleportal-weekly-mcp` 整个文件夹放到你的技能目录（WorkBuddy 是 `~/.workbuddy/skills/`），重启客户端或新开会话即可生效。

## 三、怎么用

**直接用大白话问就行，不用记命令。** 例如：

- 「拉一下本周的运营周报数据」
- 「上周抽奖活动参与情况怎么样，哪些活动掉得厉害」
- 「本月社群消息 Top10 群是哪些」
- 「小程序昨天的数据，和上周同期比如何」
- 「对比一下最近两周的抽奖、社群、小程序三块数据」

AI 会自动识别时间范围、调用对应的数据接口，然后把结果整理成人话给你。

---

## 四、你会得到什么

默认产出是**聊天里的分析结论**（含数据表）。一次标准查询包含三大块：

### 📊 抽奖活动（lottery）
- 本周 / 上周参与记录数、参与人数（去重）、环比
- 按活动后缀分组（zys / gyp / lxc / wyy / mxl）的分组对比
- 跌幅大的分组会被单独标出来预警

### 💬 企微社群（chatdata）
- 本周 / 上周消息总数、发言人数、群数、成员数、环比
- TOP-N 活跃群排行（群名 + 消息数）

### 📱 小程序（wxmp）
- 打开次数、访问人数、新访问用户、停留时长、访问深度
- 日 / 周 / 月三个维度的增长率
- 近 7 天趋势数据

如果你要**表格**、**图表**或**导出文件**，直接跟 AI 说，它会基于拿到的数据现做（数据已经在它手上，不需要重新查询）。

### 要一份可分享的 HTML 看板？

直接跟 AI 说「**出一份周报看板**」或「**生成 HTML 报告给我**」。它会在**你的电脑上**把数据渲染成一个单文件网页（含图表和复盘分析），你直接双击就能打开，也可以发给别人。

> 渲染用的是本技能自带的模板，在你本机完成，**不经过服务器生成文件** —— 所以你拿到的就是自己机器上的文件，不存在"报告留在服务器上拿不到"的问题。

## 五、几个要注意的点

1. **数据来自生产环境，是实时查询的** —— 每次问都是现拉最新数据，不是缓存快照。
2. **所有使用者查到的是同一个项目的数据** —— 服务端凭据固定，意味着数据范围固定。如果你需要查别的项目，联系管理员调整服务端配置。
3. **小程序数据是 T+1 的** —— 查"今天"通常没数据，默认看昨天。
4. **`累计访问用户数` 只增不减**，它的"增长率"没有参考意义，看趋势请用`打开次数`和`访问人数`。
5. **社群数据全为 0** 通常意味着该项目没开通企微会话存档，不代表社群真的没活跃。

## 六、出问题怎么判断

| 提示 | 含义 | 谁来处理 |
|---|---|---|
| `Missing OpenAPI config` | 服务端没配业务凭据 | 管理员 |
| `No such command 'weekly'` | 服务端 CLI 版本缺失 | 管理员 |
| 连接失败 / 401 | MCP 地址或 Token 填错 | 你自己检查配置 |
| `Input should be a valid string` | 违反调用规范（参数应走 argv） | 已在本技能内规避，若复现请反馈 |

需要 curl 直连排查时，向管理员索取调试示例 —— 本公开版不含服务端运维文档。
